# Where the PDFium in our packages comes from, and how to tell.
#
# PDFium is the one foreign binary that enters a PreppSuite package without
# being built here. It is downloaded at build time -- previously by the
# plugin's CMake, since pdfrx 2.4.8 by `pdfium_dart`'s build hook -- and
# neither of them checks what arrives. This file is that check.
#
# The numbers below are not "whatever we downloaded once". They come from
# the SLSA provenance attestation that GitHub signs for every
# bblanchon/pdfium-binaries release: `pdfium-attestation.json` carries a
# SHA-256 for each archive, and the library hashes here were taken from
# archives that matched it.
#
# macOS is the exception, and not a gap: the dylib is placed in a framework
# and ad-hoc signed during the build, so its bytes necessarily differ. The
# Mach-O UUID does not change when a binary is signed, so that is what is
# compared there -- one per architecture, because the framework is
# universal.
#
# Refreshing this after a pdfium_dart bump: read `_pdfiumRelease` out of
# the package's `hook/build.dart`, fetch that release's attestation, and
# redo the table. tool/pdfium_provenance.sh --help says how.
